Develop統合

1. 共通部分で直したもの

■ Recipe.java
- 松下ブランチ側を基準に統一
- reading / ingredientsReading を1つずつ保持
- 赤羽根ブランチにあった reading の二重定義、getter/setterの重複は入れていない
- DB列名は snake_case に統一
  cooking_time
  favorite_level
  ingredients_reading
  created_at
  updated_at

理由：
Entityとschema.sqlの名前も揃えておかないと、統合後にDB周りで混乱しやすいため。

■ pom.xml
- Kuromoji依存関係ありの版に統一
- com.atilika.kuromoji:kuromoji-ipadic:0.9.0

理由：
Recipe.javaとKuromojiUtilsを共通基盤として使うため。

■ schema.sql
- reading / ingredients_reading を含む版に統一
- cookingTime等のcamelCaseをEntity側と同じsnake_caseへ統一
- 末尾の余計なカンマを削除

理由：
ブランチごとにDB列名が違っていたため。


■ KuromojiUtils.java
- 松下ブランチの共通クラスを採用
- 登録、編集、検索で同じ変換処理を使える状態


■ DataLoader.java
- readingが無い既存データだけ補完する処理を残した

理由：
すでに保存済みのデータだけreadingが空になる状態を避けるため。


2. RecipeController.java

■ / と /recipes の重複を整理
- / は /recipes へredirect
- 一覧表示は /recipes に統一
- Model名は recipes に統一

理由：
ブランチごとに / と /recipes で別の一覧処理があり、data と recipes も混在していたため。
このままマージすると、どちらの一覧処理を使っているのか分かりづらくなる。


■ 新規登録
- 現在動いている基本登録処理だけ残した
- 登録時のKuromoji読み生成はこちらでは追加していない

理由：
赤羽根さん担当の未実装部分をこちらで完成させないため。


■ 編集
- 松下ブランチの編集処理を残した
- 編集時のreading / ingredientsReading再生成を残した
- currentImage方式は使わず、画像未変更なら既存画像をそのまま保持


■ 詳細・削除
- None

理由：
河野さん担当で、現在detail.htmlはあるがGET詳細とPOST削除はまだ未実装のため。


3. RecipeRepository.java

森口さんブランチの検索用メソッドは残した。
ただしSpring Data JPAで起動時にエラーにならないよう、
Andで2項目を指定しているメソッドは引数も2つに揃えた。

例：
findByReadingAndIngredientsReadingOrderByUpdatedAtDesc(
    String readingKeyword,
    String ingredientsReadingKeyword
)

理由：
元コードはAndで2プロパティ指定なのに引数が1つだったため。
これは検索機能の完成ではなく、メソッド定義の不整合修正のみ。

※ 現状は And + 完全一致のまま。


4. RecipeService.java

- 不要importを削除
- Repositoryの引数数修正に合わせ、keywordを2引数へ渡すよう修正
- コメントを短く整理
- Controllerにはまだ接続していない

7. developへ上げる前の確認

Windows / VS Codeのプロジェクト直下で実行：

.\mvnw.cmd -U clean compile

BUILD SUCCESSを確認。

その後：
.\mvnw.cmd spring-boot:run

現時点で確認する範囲：
- 一覧が開く
- 新規登録ができる
- 編集画面が開く
- 編集保存ができる
- 起動エラーが出ない
